# OTT PROJECT 클릭형 목업

Spotify 기반 표면·카드, Runway 배너, 밝은 관리자 화면을 적용한 브라우저 목업이다. 실제 서버 서비스가 아니라 UI 흐름 검토용이다.

## 실행

`dist/index.html`을 브라우저에서 열거나 이 디렉터리에서 `python3 -m http.server 4173 --directory dist`를 실행하고 `http://localhost:4173`을 연다. 외부 패키지 설치가 필요하지 않다.

## 시연

오른쪽 아래 시연 도구에서 신규 회원, 기존 회원 A/B, 관리자를 선택한다. 신규는 소셜 인증 모의 화면과 닉네임 입력을 거친다. 기존 회원은 다른 찜·이력·추천을 갖는다.

관리자는 콘텐츠 추가·편집·삭제·공개 전환, 원본 등록 상태·처리 재시도, 인기 콘텐츠 자동 집계 조회, 라이브 채널·편성표 검증, 모의 학습·감사 기록 조회를 사용할 수 있다. 변경은 브라우저 저장소에만 보관되며 초기화 버튼으로 복원한다.

## 모의 처리 범위

소셜 OAuth·서버 세션, 실제 영상/스트림·DRM·ABR, 파일 전송·변환, 추천 모델 학습·추론은 구현하지 않았다. 재생은 시연용 타임라인이다. 파일 선택은 이름과 상태만 저장한다. 실제 계정 정보나 비밀값을 입력하지 않는다.

브라우저 목업의 변경은 Figma 파일에 자동 반영되지 않는다. 수정 기준은 프로젝트 루트 DESIGN.md와 Notion 원본 FR-01~32다. 기존 PDF는 v0.1 참고본이다.

## 점검

`node check.mjs`는 격리된 JavaScript 환경에서 입력·권한 분기·데이터 분리·편성·학습 실패 등 핵심 동작을 검사한다. 실제 브라우저 검수와는 별도다.

## 인기 추천 시연 기준

홈의 인기 목록과 관리자 인기 콘텐츠 화면은 같은 집계 함수를 사용한다. 최근 7일간 작품별 30초 이상 시청한 고유 사용자 수로 정렬하고, 동률이면 누적 시청 시간·콘텐츠 ID 순으로 정렬한다. 반복 시청은 사용자 수를 중복 계산하지 않는다. 샘플 시청 데이터와 이 브라우저의 실제 재생 타이머 진행분을 합산하며 탐색으로 이동한 위치·일시정지·관리자 재생은 집계하지 않는다. 비공개·삭제 콘텐츠는 제외하고 집계 데이터가 없으면 홈은 최신작으로 대체한다. 기간·30초·순위 산식은 목업의 제안값이며 실제 구현 때 확정한다. 다른 방문자의 데이터는 합산하지 않는다. 기존 수동 추천 상태는 이전 버전에서 전환 시 사용하지 않는다.

## CMS 연결 (v0.3 추가)

`dist/cms-config.js`에 CMS 서버 주소가 정해지면 시청자 화면(홈·검색·상세)은 CMS API에서 데이터를 조회하고, 재생 화면은 스트리밍 서버의 HLS API를 사용한다. 기본 스트리밍 주소는 CMS 호스트의 8081 포트이며, 별도 주소를 쓸 때는 같은 파일에서 `STREAMING_SERVER`를 설정한다. 주소가 없거나 CMS에 연결하지 못하면 예전처럼 내장 샘플 데이터와 시연용 타임라인으로 동작한다.

- 바뀐 파일: `dist/app.js`(CMS 연결 코드, `[CMS 연결]` 주석 참고), `dist/index.html`(스크립트 2줄 추가)
- 추가된 파일: `dist/cms-config.js`(서버 주소), `dist/hls.min.js`(HLS 재생 라이브러리 hls.js 1.5.20, Apache-2.0)
- 바뀌지 않은 파일: `dist/styles.css`, `dist/assets/*`
- 관리자 화면, 로그인, 찜·이어보기·인기·추천은 아직 브라우저 안의 모의 동작이다.
- `node check.mjs`의 기존 검사 47개는 그대로 통과한다. (CMS 주소가 없는 상태로 검사)
